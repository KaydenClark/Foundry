# Gatehouse - Lexicon

This Hall has no vocabulary of its own yet. The terms it will operate on are
already defined at GPT_OS root `LEXICON.md` and are not redefined here to
avoid a second, drifting copy. Read the root entries; this file only indexes
which ones the Gatehouse is expected to own once it has an implementation.

| Term | Owned at | Gatehouse relevance |
|---|---|---|
| **Hall** | GPT_OS root `LEXICON.md` | The Gatehouse is one of the four; see the entry for the full-tier definition. |
| **the Gatehouse** | GPT_OS root `LEXICON.md` | This Hall's own charter of record. Quoted in full in `BLUEPRINT.md`. |
| **Job Order** | GPT_OS root `LEXICON.md` | The badge the Gatehouse is meant to assign and scan. Not implemented. |
| **Pawn** | GPT_OS root `LEXICON.md` | A deterministic, non-model actor. The Gatehouse's eventual workforce; none exist yet. |
| **Agent** | GPT_OS root `LEXICON.md` | Contrast term for Pawn: deliberates under a role and a Job Order. |
| **Socket** | GPT_OS root `LEXICON.md` | A capability contract housed inside a Hall. The Gatehouse does not house a socket today. |
| **clearance band** | GPT_OS root `LEXICON.md` -> **the Gatehouse** | What per-plane verification enforces; not yet designed. |

When this Hall gets its first real implementation, terms it actually
introduces (a gate-check name, a Job-Order schema field, a Pawn class) belong
here, following the same "load it whole, speak its terms" pattern the root
Lexicon documents.
